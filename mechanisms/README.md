# Механизмы: карточки, граф связей и принципы

**Статус:** Informative, пилот (версия 0.1). Содержимое не вводит требований и не меняет правила claim.

## Зачем это нужно

Реестр из 119 механизмов ([`docs/BIOLOGY_TO_IT_MAPPING.md`](../docs/BIOLOGY_TO_IT_MAPPING.md)) говорит, что делает механизм в системе и как его проверить. Он не говорит, как биологический механизм устроен и как работает, и не показывает, как механизмы связаны друг с другом. Этот раздел закрывает оба пробела, не меняя нормативный реестр.

## Что в карточку попадает

Механизм получает карточку, только если из него следует переносимый инженерный принцип и хотя бы одно проверяемое правило или тест. Иначе это биология без пользы для стандарта (`CONTRIBUTING.md`). Каждое утверждение о биологии ссылается на статью; выводы автора помечены отдельно.

## Как использовать граф

```bash
python scripts/analyze_interaction_graph.py
```

Скрипт показывает самые связанные механизмы (кандидаты на карточки в первую очередь), механизмы без входов, без выходов и без связей (кандидаты на пробелы в описании) и петли усиления. Петля усиления без ограничителя `H-02` считается ошибкой, её ловит валидатор репозитория.

## Ограничения

- Граф неполный и написан автором без независимой проверки: отсутствие связи не означает отсутствия зависимости. Основание каждой связи указано, чтобы её можно было оспорить.
- Карточки опираются на рефераты статей PubMed; полные тексты не читались. Проверка биологом не проводилась.
- Принципы и идеи проверок не являются требованиями: нормативным правилом они становятся только через порядок `GOVERNANCE.md`, раздел 4.
