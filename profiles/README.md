# Профили внедрения DOA

**Статус:** Informative.

## Что это

Профиль внедрения показывает, как выполнить требования DOA в конкретной архитектуре: какие понятия стандарта чему соответствуют, какие пределы у этой архитектуры и как их компенсировать. Это не профиль соответствия: он не добавляет требований, не меняет правила claim и не даёт права писать «DOA-compliant». Соответствие по-прежнему определяют требования стандарта и evidence ([`docs/CONFORMANCE.md`](../docs/CONFORMANCE.md)).

## Как пользоваться

1. Выберите профиль, ближайший к вашей архитектуре.
2. Пройдите по таблице требований профиля и отметьте пределы, которые относятся к вам.
3. Соберите evidence по кейсам [Verification Kit](../docs/VERIFICATION_KIT.md).
4. Оформите claim с честными статусами; пределы архитектуры укажите в разделах `scope` и `exclusions`.

## Доступные профили

| Профиль | Для чего | Состояние |
|---|---|---|
| [Модульный монолит](modular-monolith.md) | одно развёртываемое приложение с модулями | готов к использованию, не проверен независимой реализацией |
| Kubernetes и потоки событий | распределённая система из сервисов | запланирован |
| Edge и робототехника | физические системы, реальное время | запланирован |
| Изолированные сети и высокая надёжность | закрытые контуры, повышенные требования к доказательствам | запланирован |

Нет подходящего профиля? Откройте issue по форме «Standard gap» или расскажите о своём опыте в форме «Application report».
